4.3 Consulta de Dados

Como o C# recebe os dados de um SELECT?
Através do MySqlDataReader, que percorre os resultados linha por linha, sem carregar tudo de uma vez na memória.

Como percorrer os resultados?
Com while (reader.Read()) e cada chamada avança pra próxima linha, e para quando não há mais registros.
É assim que o ListarPessoas()funciona:

csharp
while (reader.Read())
    pessoas.Add(CriarDoReader(reader));

Como transformar os dados em objetos da classe?
O projeto faz isso no método CriarDoReader, que monta um objeto Imc direto com os valores lidos do banco:

csharp
private static Imc CriarDoReader(MySqlDataReader reader)
{
    return new Imc
    {
        Id = reader.GetInt32("id"),
        nome = reader.GetString("nome"),
        peso = reader.GetDecimal("peso"),
        altura = reader.GetDecimal("altura")
    };
}

Aqui os campos são preenchidos diretamente (sem passar pelos setters com validação),
porque os dados que já estão salvos no banco são considerados válidos.

4.4 Segurança

O que são parâmetros em comandos SQL e por que são importantes?
São os @nome, @peso, @altura, @id usados em todos os comandos do Imc.cs, 
preenchidos via cmd.Parameters.AddWithValue(...). O valor é enviado separado do texto do comando SQL,
então o banco nunca interpreta o que o usuário digitou como parte do comando — só como dado puro.
O que pode acontecer ao montar SQL concatenando texto digitado pelo usuário?
Abre brecha para SQL Injection. Se o projeto tivesse feito, por exemplo:

csharp
// PERIGOSO — não é assim que o projeto faz
string sql = "INSERT INTO Pessoa (nome) VALUES ('" + Nome + "')"

alguém poderia digitar no campo nome algo como '); DROP TABLE Pessoa; -- e apagar a tabela inteira do banco, 
ou manipular outros comandos SQL sem autorização. 
Como o projeto usa parâmetros (AddWithValue) em todos os comandos,esse risco é evitado.
